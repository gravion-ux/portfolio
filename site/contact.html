What to include in an enquiry

It saves a round trip if the first message covers these four points:

  1. What you need. An assessment, a code review, an automation build, or a sponsorship question.
  2. The target. For an assessment: the application or API, and roughly how many endpoints or services are in play. For a code review: the repository or the pull requests.
  3. Authorization. That you own the targets, or are authorized in writing to test them. Testing does not begin before that exists.
  4. Your deadline. What you need the result by, and anything hard about it — a compliance date, a launch, a production freeze.
Scope is agreed in writing before any testing. If you cannot confirm ownership or authorization of a target, I will say so and suggest where to go instead. That is not negotiable, and it is the reason the work has any value.
