Why sponsorship, and why this way

Open-source security tooling has a funding problem that nobody solves by writing more documentation. Sponsorship pays for the parts nobody sees: triage on issues that arrive from strangers, CI maintenance, dependency review of my own tools, and the next release. That is what a sponsor is buying, and it is why the tools stay free and free of telemetry.

All 30 published projects are MIT licensed, 22 of them run a CI workflow, and 28 have a test suite whose size was measured. The tools are free to use without an account. There is no upsell path, no telemetry, and no lock-in. If a sponsor ever stops paying, the tools keep working exactly as before.

Every number on this site was measured. Test counts come from running each repository's own suite on a fresh clone. Star counts come from the live GitHub API at build time. Nothing here is estimated.

How I work

  1. Read the code path first, before running tools.
  2. Reproduce the bug with the smallest possible proof.
  3. Quantify the impact in the business terms the engineer cares about.
  4. Write the fix as a code suggestion, not just an observation.
  5. Measure before and after, and quote only the numbers a command produced.
